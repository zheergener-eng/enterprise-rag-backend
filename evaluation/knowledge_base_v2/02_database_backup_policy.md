# 数据库备份与恢复管理规范

## 1. 文档说明与适用范围

本文档定义各项目、各环境数据库的备份与恢复管理要求，适用于数据库管理员、运维工程师及相关值班人员。数据库备份是保障数据可恢复性的最后一道防线，各项目、各环境的备份策略必须明确区分，不得混用。

备份文件的安全与访问控制要求，以《权限控制与安全审计规范》为准。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 全量备份 | 对数据库完整数据集进行的备份 |
| 增量备份 | 仅备份自上次备份以来发生变化的数据 |
| 保留周期 | 备份文件在删除前保留的时间长度 |
| 完整性检查 | 恢复前对备份文件可恢复性的校验 |
| 备份窗口 | 允许执行备份操作的时间段 |

## 3. 各项目备份时间

| 对象 | 备份时间 | 备份类型 |
| --- | --- | --- |
| 星河项目生产库 | 每日凌晨 2:30 | 全量备份 |
| 天枢项目生产库 | 每日凌晨 1:00 | 全量备份 |
| 测试环境数据库 | 每日凌晨 4:00 | 全量备份 |
| 临时验证环境 | 按需执行 | 按需 |

各项目、各环境的备份时间相互独立，严禁将不同对象的备份任务混用同一调度。备份任务必须在规定的备份窗口内启动，避免与业务高峰冲突。

## 4. 各项目备份保留周期

| 对象 | 保留周期 |
| --- | --- |
| 星河项目生产库 | 14 天 |
| 天枢项目生产库 | 30 天 |
| 测试环境数据库 | 7 天 |
| 临时验证环境 | 最多 3 天 |

保留周期到期后，备份文件将按计划被清理。不同项目的保留周期差异明显，务必在恢复时先确认来源项目与对应保留规则，避免误用其他项目的备份文件。

## 5. 备份执行流程

每次备份按以下流程执行：

1. 备份前确认数据库状态正常、无锁表或长事务阻塞；
2. 在备份窗口内启动备份任务；
3. 备份完成后校验文件是否生成完整；
4. 记录备份结果与备份文件标识。

备份任务是否成功，以「文件生成完整且校验通过」为准，而非仅以「任务已启动」为准。

## 6. 备份文件管理

备份文件按「项目 + 环境 + 日期」进行标识，便于追溯。备份文件应存放在与生产库隔离的存储位置，避免与业务数据相互影响。备份文件的加密与访问控制要求，以《权限控制与安全审计规范》为准。

## 7. 恢复前检查

任何恢复操作前，必须先对备份文件进行完整性检查，确认文件可恢复后方可执行恢复。恢复操作必须登记工单，记录恢复对象、来源备份、执行人与结果。

## 8. 恢复流程

恢复操作按以下流程执行：

1. 确认恢复目标与来源备份文件；
2. 对来源备份文件进行完整性检查；
3. 登记恢复工单，明确恢复范围；
4. 执行恢复，并验证数据一致性；
5. 记录恢复结果并归档。

## 9. 备份监控与告警

备份任务由统一调度系统管理。备份任务失败或未按时完成时，调度系统自动触发告警并通知值班工程师。值班工程师需确认失败原因，登记处理过程，并按《生产故障响应与升级规范》执行升级。

## 10. 定期恢复演练

为验证备份文件的可恢复性，各项目应定期进行备份恢复演练。演练需记录演练对象、演练结果与发现的问题。恢复演练用于验证备份有效性，不用于替代日常备份。

## 11. 备份与恢复工单要求

- 备份任务异常（含失败、未按时完成）必须登记工单；
- 恢复操作必须登记工单；
- 工单需记录操作时间、操作对象、执行结果。

## 12. 注意事项

- 全量备份与增量备份的文件性质不同，保留规则以「保留周期」为准；
- 测试环境与生产环境的备份文件不得交叉使用；
- 备份文件不得与 Redis 快照文件混淆，二者属于不同系统、不同用途；
- 备份文件保留周期到期清理属于计划内操作，需记录清理结果；
- 备份文件的访问遵循最小权限原则，防止越权读取或篡改。

## 13. 异常处理

备份任务失败后，值班工程师应第一时间登记事件单并按《生产故障响应与升级规范》升级。备份失败属于需要登记和升级的异常场景，不得因「次日自动重跑」而忽略。
