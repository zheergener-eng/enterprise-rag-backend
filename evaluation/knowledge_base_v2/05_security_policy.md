# 权限控制与安全审计规范

## 1. 文档说明与适用范围

本文档定义权限控制、安全审计与敏感信息管理要求，适用于全体工程与运维人员。安全原则贯穿数据库、Redis、服务器等所有组件的日常操作。

本文讨论「加密」等安全措施的一般要求。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 最小权限 | 仅授予完成工作所必需的最小权限 |
| 审计日志 | 记录关键操作以便追溯的安全日志 |
| 密钥管理 | 对密钥的生成、存储、轮换与撤销的管理 |
| 数据分级 | 按敏感程度将数据分为公开、内部、机密等级 |

## 3. 角色与权限分级

系统角色按职责划分，主要包括：

- 开发与测试角色：仅可操作测试环境；
- 运维角色：可操作生产环境，但需审批；
- 数据库管理员：负责数据库相关高危操作；
- 安全角色：负责安全审计与权限复核。

各角色权限按最小权限原则授予，不得越权操作。

## 4. 权限原则

- 最小权限原则：任何账号只拥有完成本职工作所需的最小权限。
- 生产环境访问需要审批，审批通过后方可临时授权。
- 高权限操作（数据库高危操作、权限变更等）需要审计。

## 5. 访问控制

生产环境访问通过受控入口进行，访问操作需登记，便于追溯。临时授权的访问权限应在任务结束后及时回收，避免权限残留。

## 6. 审计日志

| 项目 | 保留周期 |
| --- | --- |
| 审计日志 | 90 天 |

以下操作必须记录审计日志：

- 登录失败；
- 权限变更；
- 数据库高危操作。

审计日志保留 90 天，到期后按计划归档或清理。审计日志不得记录任何密钥或明文密码。

## 7. 账号生命周期

账号的申请、变更与回收需遵循统一流程：

- 账号申请需说明用途与所需权限；
- 员工离职或转岗时，应及时回收账号与权限；
- 长期未使用的账号应定期清理或冻结。

## 8. 密码与密钥管理

- 密码需满足复杂度要求（至少 12 位，含大小写字母、数字与特殊字符），并定期轮换；
- API Key、密码等敏感信息不得硬编码到源代码；
- 敏感配置通过环境变量或密钥管理系统管理；
- 密钥应定期轮换，泄露后立即撤销并重新签发。

## 9. 数据分级

数据按敏感程度分为公开、内部、机密三级。机密数据（含密钥、口令、核心业务数据）的存储与传输必须采用加密措施，访问需额外审批。

## 10. 加密要求

对存储与传输中的敏感数据，应采用加密措施；具体算法与强度按公司安全基线与合规要求执行。涉及数据库备份文件、Redis 快照等数据的加密方案，应遵循统一安全基线。

## 11. 生产日志要求

生产日志禁止直接记录密钥或密码。日志中若出现疑似密钥内容，应立即脱敏并排查来源。日志的访问也应受控，防止敏感信息泄露。

## 12. 安全事件上报

发现疑似安全事件（越权访问、信息泄露、异常登录等）时，应立即上报安全角色并登记，不得隐瞒或拖延。安全事件处理过程需记录并复盘。

## 13. 安全意识与培训

定期开展安全意识培训，覆盖密码管理、敏感信息保护、越权风险等内容，提升全员安全意识。

## 14. 责任边界

权限与安全审计的具体责任人、审批流程，按项目责任矩阵执行。

## 15. 数据传输加密

敏感数据在网络上传输时，应采用加密通道，防止在传输过程中被窃取或篡改。涉及机密数据的跨网络传输，需使用加密传输协议并保留访问记录。

## 16. 第三方访问管理

外部合作方或第三方需要访问内部系统时，应遵循最小权限原则，通过审批后临时授权，并在任务结束后及时回收权限与账号。第三方访问过程应纳入审计范围。

## 17. 审计核查

安全角色定期对审计日志进行核查，识别越权、异常登录与未授权操作。核查发现的问题应登记并跟进处理。
