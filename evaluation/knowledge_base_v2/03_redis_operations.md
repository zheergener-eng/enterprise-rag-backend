# Redis 部署与运维规范

## 1. 文档说明与适用范围

本文档定义 Redis 的部署、持久化、监控与故障恢复要求，适用于 Redis 维护人员及相关值班工程师。Redis 用于缓存、session 和临时状态，是提升访问性能与支撑会话的关键组件。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| RDB | Redis 在内存数据快照基础上生成的二进制持久化文件 |
| AOF | 记录 Redis 写命令日志的持久化机制 |
| 主从 | 一个主节点与若干从节点构成的数据复制关系 |
| 哨兵 | 负责监控主节点并在故障时执行切换的组件 |
| 淘汰策略 | 内存不足时决定淘汰哪些 key 的规则 |

## 3. 部署方式

Redis 默认服务端口为 6379。生产环境采用「主从 + 哨兵」方案：

- 一个主节点承载写入；
- 多个从节点承载读取与数据冗余，并实时同步主节点数据；
- 哨兵进程负责监控主节点状态，并在主节点故障时触发切换。

所有环境均启用密码认证，端口不对外网开放，仅允许内网指定网段访问。

## 4. 用途

Redis 在星河项目中的用途包括：

- 缓存：缓存热点数据，降低数据库查询压力；
- session：存储部分会话状态；
- 临时状态：存放短期有效的临时数据。

## 5. 持久化：RDB 与 AOF

Redis 的持久化与数据库备份不是同一个概念。Redis 持久化解决「内存数据重启后恢复」的问题：

- RDB：定期对内存生成快照文件，用于快速恢复；
- AOF：记录写命令日志，用于更细粒度的数据恢复。

生产环境同时开启 RDB 与 AOF，二者互为补充：RDB 提供快速恢复，AOF 提供更细粒度的数据保护。

## 6. 快照与日志保留策略

| 项目 | 保留策略 |
| --- | --- |
| RDB 快照文件 | 保留 3 天 |
| AOF 日志 | 与快照同周期轮转，保留最近 3 天 |

超过保留周期的快照文件与 AOF 日志将按计划清理。快照文件保留周期与数据库备份保留周期是两个独立策略，不可混为一谈。

## 7. AOF 重写

为避免 AOF 日志无限增长，当 AOF 文件增长超过 100% 且大小超过 64MB 时，Redis 会触发 AOF 重写，对日志进行压缩整理。重写过程不影响主节点正常对外服务。

## 8. 内存淘汰策略

当 Redis 内存不足时，按淘汰策略决定哪些 key 被淘汰。生产环境默认采用 allkeys-lru 策略，优先淘汰最近最少使用的 key。维护人员不得随意修改淘汰策略，调整需在变更窗口内进行并经过审批。

## 9. 高内存使用率排查

当 Redis 内存使用率超过 75% 触发告警时，按以下步骤排查：

1. 定位大 key，确认是否存在异常膨胀；
2. 检查 key 的过期策略是否生效；
3. 评估是否需扩容或迁移数据；
4. 必要时在变更窗口内调整。

## 10. 主从同步监控

值班巡检需确认主从同步状态正常，主从同步延迟应保持在可接受范围内。若同步延迟异常增大，需排查网络、主节点负载与从节点磁盘 I/O，必要时登记处理。

## 11. 容量规划

Redis 内存容量按缓存体量与增长趋势定期评估，避免频繁触发淘汰或告警。容量不足时，应在变更窗口内完成扩容或数据迁移，不得等到内存告警后才被动处理。

## 12. 日常操作清单

Redis 维护人员的日常操作包括：

- 检查主从同步是否正常；
- 检查内存使用率与慢日志；
- 检查异常日志与连接数；
- 检查持久化文件是否正常生成。

## 13. 主从切换与故障恢复

主节点故障时，哨兵通过监控判定主节点下线并自动触发切换，将某从节点提升为主节点。切换完成后需验证读写是否恢复正常，并检查从节点是否重新完成同步。整个切换过程必须登记事件单。

## 14. 危险命令管控

禁止在生产环境直接执行可能影响数据安全或阻塞服务的危险命令，包括但不限于全量清理类命令。危险命令操作必须在变更窗口内、经过审批后执行，并保留审计记录。

## 15. 与数据库备份的关系

Redis 的持久化（快照与 AOF）与数据库备份解决的是不同问题，不得互相替代，也不得用「Redis 有快照」来规避「数据库备份」的要求。

## 16. 监控指标

Redis 需重点监控以下指标：

- 内存使用率；
- 命中率；
- 连接数；
- 主从同步延迟；
- 慢查询数量。

指标异常时，按对应章节的排查步骤处理。
